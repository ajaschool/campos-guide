관리자 홈

운영자가 매일 여는 화면

화면만 봐도 “지금 뭘 해야 하는지”가 보이도록 만들었습니다. 할 일·공지·진행 현황이 한 화면에 모입니다.

관리자1

전체 대시보드

맨 위 “처리할 일”이 모든 행사에서 해야 할 일을 한 줄씩 모아 줍니다. 그 아래로 진행 중인 행사, 준비/진행/완료 현황, 달력과 공지가 이어집니다.

무슨 화면

운영자의 출근 첫 화면. 여러 행사를 동시에 맡아도 해야 할 일과 진행 상황을 한눈에 파악합니다.

이렇게 씁니다

  1. 맨 위 ‘처리할 일’에서 밀린 일 확인
  2. 긴급·전체·행사별로 필터링
  3. 항목을 누르면 해당 작업 화면으로 바로 이동

설계 포인트

‘처리할 일’이 모든 할 일이 모이는 단 하나의 통로입니다. 할 일 페이지·행사 상세에서도 같은 목록을 그대로 봅니다.

맨 위 ‘운영 현황’ 띠 — 행사 상태에 따라 모습이 바뀝니다
대시보드 최상단의 가로 띠 하나로 “지금 챙길 행사가 무엇인지”를 알려 줍니다. 진행 중인 행사가 있으면 그 행사를, 없으면 가장 임박한 준비 중 행사를 보여 줍니다.

🟢 진행 중일 때

초록 ‘LIVE’ 띠. 지금 운영 중인 행사명과 ‘운영 현황 →’이 떠, 누르면 그 행사로 바로 들어갑니다. 진행 중 행사가 여럿이면 가장 먼저 시작한 행사를 보여 줍니다.

⚪ 시작 전일 때

회색 ‘D-N’ 띠. 진행 중 행사가 없으면, 시작이 가장 가까운 준비 중 행사를 D-day와 함께 띄웁니다.

⚫ 행사가 없을 때

비활성 띠. 진행 중·준비 중 행사가 모두 없으면 “예정된 행사가 없어요 · 행사 만들기”만 보입니다.

관리자1

할 일

시스템이 스스로 찾아낸 일과 관리자가 직접 적은 일을 하나의 목록으로 합칩니다.

무슨 화면

자동으로 감지된 일(참가자 미등록·멘토가 안 배정된 팀 등)과, 관리자가 손으로 추가한 일을 함께 관리합니다.

이렇게 씁니다

  1. 자동 감지 항목은 그대로 떠 있음
  2. ‘+ 할 일 추가’로 직접 등록 — 행사 지정도, 행사와 무관하게도 가능
  3. 끝내면 체크

설계 포인트

대시보드·할 일 페이지·행사 상세 어디서든 추가할 수 있습니다. 표준 체크리스트 항목은 실제 운영을 거치며 확정해 나갈 예정입니다.

📌 처리 상태 — 할 일은 [처리할 일] / [완료한 일] 탭으로 나뉩니다. 처리하면 누가·언제 처리했는지 기록되고, 자동 감지 항목은 원인이 해소되면(예: 참가자 등록을 마치면) 목록에서 저절로 사라집니다.
관리자1

공지

관리자끼리 보는 ‘내부 공지’와, 현장(멘토·스태프)에 내려보내는 ‘행사 공지’를 분리했습니다.

무슨 화면

두 종류의 공지를 한 곳에서 작성·관리합니다. 행사 공지는 받을 대상(관리자/멘토/스태프)과 긴급도를 지정합니다.

이렇게 씁니다

  1. 내부/행사 탭을 골라 작성
  2. 행사 공지는 대상과 긴급/일반을 선택
  3. 등록하면 해당 앱에 바로 도착

설계 포인트

공지는 관리자 → 현장으로 내려가는 단방향입니다. 반대로 현장이 올리는 통로는 ‘현장 보고’로 따로 두었습니다.

📌 읽음과 상태 — 행사 공지를 받으면 멘토 앱 벨에 빨간 점이 켜지고, 멘토가 확인하면 사라집니다(본인 확인용). 관리자 쪽 공지는 미처리 / 해결 상태로 따로 관리합니다.
관리자1

행사를 가로지르는 두 화면 — 멘토 풀 · 전역 스케줄

대부분의 작업은 ‘행사 하나’ 안에서 이뤄지지만, 좌측 메뉴의 멘토와 스케줄은 여러 행사를 한 번에 모아 봅니다. 같은 멘토가 이 행사 저 행사를 오가고, 일정도 행사별로 흩어져 있어서요.

멘토 풀 (좌)

지금까지 등록된 모든 멘토를 한 명씩 봅니다. 각 멘토가 현재 어느 행사에 참여 중인지, 총 몇 번 참여했는지, 마지막이 언제였는지가 한 줄에 모입니다. 활성/대기/비활성으로 거르고 이름·전화로 검색해요.

전역 스케줄 (우)

모든 행사의 일정을 날짜별로 합쳐 봅니다. 행사·상태로 걸러 “오늘 어느 행사에서 무슨 일정이 도는지”를 한눈에 파악하고, 일정을 누르면 해당 행사 상세로 바로 들어갑니다.

설계 포인트

행사 안의 화면이 ‘이 행사’에 집중한다면, 이 두 화면은 ‘행사들 사이’를 잇습니다. 멘토 한 명의 이력과 모든 일정을 행사 경계 없이 훑을 수 있게 따로 빼 두었습니다.

관리자1

행사 목록

진행 중·준비 중·완료된 모든 행사를 한 곳에서 관리합니다. 여기서 행사 하나를 골라 들어가면 — 지금부터 그 행사의 일생을 따라가 봅니다.

준비

행사를 만들고 명단·팀·일정을 채웁니다

관리자1이 행사를 생성하고 → 참가자 명단을 올리고 → 팀을 나누고 → 스케줄을 등록합니다. 멘토·메딕이 들어오기 전, 관리자 혼자 준비하는 단계입니다.

관리자1

행사 생성

필수 정보, 담당자, 출석체크 방식을 한 번에 설정해 행사를 만듭니다.

무슨 화면

행사명·유형(1일형/숙박형)·주관기관·기간 같은 기본값과, 담당자 3인(PM·PD·AD), 출석 옵션을 정합니다.

이렇게 씁니다

  1. 필수 정보 입력 (임시저장 가능)
  2. 담당자 3인 지정 + 기타 인력 자유 추가
  3. 선탑·중앙 출석을 쓸지 체크하고 생성

설계 포인트

역할이 고정된 3인은 정해진 칸으로, 매번 달라지는 기타 인력(촬영·안전요원 등)은 자유 형식으로 받아 — 구조와 유연성을 같이 잡았습니다.

관리자1

참가자 등록 · 행사 상세

엑셀 명단을 한 번에 올리면 참가자가 등록되고 집결지가 자동으로 만들어집니다. 이 행사 상세 화면이 앞으로 모든 운영의 ‘본부’가 됩니다.

무슨 화면

참가자 30명이 등록된 행사 본부. 위쪽 KPI로 인원·출석·스케줄 진행을, 좌측 메뉴로 멘토·스케줄·출석 등 모든 탭을 오갑니다.

이렇게 씁니다

  1. 양식(엑셀 템플릿)을 내려받아 명단을 채움
  2. 참가자 탭에서 엑셀 업로드 — 오류 난 행만 고쳐 다시 올리기 (중복은 자동으로 건너뜀)
  3. 좌측 메뉴로 다음 작업 이동

설계 포인트

엑셀을 ‘원본’으로 두고 시스템이 집결지 목록을 자동 생성합니다. 관리자가 손으로 집결지를 적다 생기는 오타·누락을 없앴습니다.

관리자1

참가자 한 명 자세히 보기

명단에서 참가자를 클릭하면 오른쪽에서 상세 패널이 열립니다. 인적사항·보호자 연락처·집결지, 그리고 특이사항까지 한 화면에 모입니다.

여기서 할 수 있는 것

참가자 정보 수정·삭제, 특이사항 확인. 명단에서는 이름 검색, 컬럼 정렬, 여러 명 선택 삭제도 됩니다.

특이사항이 중요한 이유

알러지·지병·적응 관련 메모가 여기 쌓입니다. 메딕이 진료할 때도, 멘토가 팀을 챙길 때도 이 정보를 함께 봅니다.

관리자1

팀 배정

자동으로 균등하게 나눈 뒤, 드래그로 손보고, 팀마다 멘토를 한 명씩 지정합니다.

무슨 화면

참가자를 팀으로 나누는 화면. 성별·나이·학과 등 기준을 골라 자동 배정하고, 각 팀에 담당 멘토를 붙입니다.

이렇게 씁니다

  1. 조 수와 배정 기준 선택 후 ‘자동 배정’
  2. 카드를 드래그해 팀 간 인원 조정
  3. 각 팀 상단에서 담당 멘토 지정

설계 포인트

자동으로 대강 만든 뒤 눈으로 다듬는 방식이 현장에서 가장 빠릅니다. 팀당 멘토는 1명 — 이미 멘토가 있는 팀에 다른 멘토를 지정하면, 기존 멘토가 자동으로 미배정으로 빠지며 교체됩니다.

관리자1

방 배정 · 숙박형 행사만

숙박형 행사면 ‘방 배정’ 탭이 생깁니다. 팀 배정과 똑같이 자동 배정 후 드래그로 조정하되, 반드시 같은 성별이 한 방에 들어갑니다.

1일형 행사에는 방 배정 탭이 아예 나타나지 않습니다 — 행사 유형(1일형/숙박형)에 따라 보이는 화면이 달라집니다.
관리자1

스케줄 등록

행사 안의 세부 일정(시간표)을 날짜별로 관리합니다. 여기 등록한 스케줄이 멘토 앱에 그대로 나타납니다.

무슨 화면

날짜·시간·장소·팀별로 일정을 등록하고 진행 상태(예정/진행중/완료)를 관리합니다. 스케줄마다 사진 업로드를 켤 수 있습니다.

이렇게 씁니다

  1. 날짜 탭을 고르고 ‘스케줄 추가’
  2. 시간·장소·담당 팀 입력
  3. 저장하면 멘토 앱 일정에 즉시 반영

설계 포인트

스케줄이 멘토 앱·출석·사진·현장 보고를 잇는 축입니다. 진행 상태가 양쪽 앱에 같이 동기화돼, 따로 맞출 필요가 없습니다.

합류

멘토와 메딕을 행사에 등록합니다

멘토·메딕이 행사에 들어오는 방법은 두 가지입니다. 하지만 결국 전화번호로 한 사람으로 모입니다 — campOS는 전화번호 자체가 계정이라, 비밀번호가 없습니다.

멘토·메딕은 어떻게 행사에 들어오나
관리자가 미리 넣어두거나(①), 멘토가 직접 가입하거나(②) — 두 길이 전화번호에서 만납니다.
① 사전등록

② 셀프신청

관리자1

멘토 초대 · 승인

행사 상세 멘토 탭에서 초대 링크를 발급하고, 들어온 신청자를 승인하거나 반려합니다.

무슨 화면

이 행사의 멘토 명단과 상태(사전등록/신청/승인/거절/만료)를 관리합니다. 초대 링크 발급, 집결지 편집, 승인·반려가 여기서 이뤄집니다.

이렇게 씁니다

  1. ‘초대 링크’로 링크를 만들어 카톡·문자로 전달
  2. 가입한 사람이 ‘신청’ 상태로 들어옴

설계 포인트

한 행사에 메딕 인원 제한이 없습니다. 여러 메딕이 함께 기록할 수 있고, 각 기록에는 누가 썼는지가 자동으로 표시됩니다.

📋 관리자 건강 탭의 두 가지 보기 — 참가자별 누적 기록과 함께, 모든 진료 기록을 한 줄씩 모은 전체 차트(작성일·시각·이름·팀·담당 멘토·증상·처치·비고)를 날짜·팀·메딕으로 걸러 봅니다. 기록을 쓴 메딕은 본인이 쓴 기록만 고치거나 지울 수 있어요.
마무리

정리하고, 기록을 남기고, 닫습니다

행사는 만들어진 순간부터 닫힐 때까지 정해진 상태를 거칩니다. 처음 보면 헷갈리기 쉬우니, 먼저 전체 상태 흐름부터 보겠습니다.

행사가 거치는 네 가지 상태
화살표 위 글자가 ‘무엇이 다음 단계로 넘기는지’입니다.

관리자1

다음 작업 · 진행 현황

행사 상세의 ‘다음 작업’ 위젯이 마무리까지 무엇이 남았는지 짚어 줍니다.

💡 ‘종료’를 누르는 순간 — 멘토·스태프 연결과 초대 링크가 모두 만료되고, 행사 전체가 읽기 전용으로 바뀝니다. 마지막 단계라 신중히 누릅니다.
관리자1

회고 — 전체 모아보기

회고는 두 군데서 만납니다. 행사별로는 진행 중 느낀 점을 카테고리(이슈/개선점/잘된 점/메모)로 그때그때 적고 — 이 화면처럼 전체 회고 페이지에서는 여러 행사에 쌓인 회고를 한곳에 모아 봅니다.

💡 행사 하나에만 머무르지 않고 여러 행사를 거치며 쌓인 교훈을 통합해 보는 화면입니다. 좌측 메뉴 ‘회고’에서 언제든 들어올 수 있어요.
결과보고서는 행사가 끝난 뒤 만드는 정리 산출물입니다. 참가자 수·출석률·이슈 요약 같은 항목이 자동으로 채워지고 관리자가 다듬습니다. (들어갈 항목은 운영하며 확정해 나갈 예정)
관리자1

활동 로그

누가 언제 무엇을 했는지가 감사 기록으로 남습니다. 자동 상태 전환, 멘토 출석, 공지 발송까지 모두 누적됩니다.

무슨 화면

행사·참가자·멘토·스케줄·공지 등 주요 행위를 시각·주체와 함께 기록합니다. 시스템이 자동으로 한 일도 따로 표시됩니다.

이렇게 씁니다

  1. 행사 상세 → 활동 로그 탭
  2. 시간순으로 행위를 추적
  3. 책임 소재와 이력을 확인

설계 포인트

‘누가 눌렀는지’를 항상 되짚을 수 있어, 여러 명이 함께 운영해도 책임과 이력이 분명하게 남습니다.

📎 이 밖에 — 관리자 계정 관리(새 관리자는 가입 신청 후 기존 관리자가 승인), 메딕 홈·공지 수신 화면도 위와 같은 패턴으로 동작합니다. 세 앱 모두 우측 상단에서 로그아웃할 수 있고, 로그아웃하면 기기에 남은 로그인 정보가 깨끗이 비워집니다.
